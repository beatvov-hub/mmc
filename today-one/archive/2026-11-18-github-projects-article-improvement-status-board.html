For Whom

こんな人向け

記事やサイトの改善依頼が会話やメモに散らばり、誰が次に何をするか見失いがちな編集・広報担当者向けです。

The Answer

結論

GitHub Projectsで記事改善の依頼を進捗別のボードに整理し、次に着手する作業を見渡せます。

How to Use

やり方／確認方法

例えば、記事の改善要望を3件だけ整理する想定例です。GitHubアカウントでProjectをBoardとして新規作成し、各要望をDraft issueで登録してタイトルと補足を書きます。カードを「未着手・作業中・確認待ち」のStatus列に分けると、次の作業と滞留箇所を一覧できます。最初は公開してよい要望だけを置き、カードの説明から次の一手が分かるか、Statusの意味が担当間で揃うか確認します。後から関連するIssueやPRも加えて、実作業へのリンクを同じボードで追えます。

Why Today

なぜ今日はこれ？

記事の改善依頼は会話、原稿、コード変更の場所が分かれ、優先順や次の担当が会話にだけ残ると着手点を探し直しがちです。ProjectsはDraft issueから始められ、必要に応じてIssueやPRも一つの進捗表示に加えられます。

Cautions & FAQ

注意点・FAQ

公開Projectはインターネット上の誰でも閲覧できます。非公開の企画や個人情報を書き込む前にProjectの公開範囲を確認し、リンク先のIssueやPRにも適切な閲覧権限を設定してください。

Issueを作る前の企画案もProjectに登録できますか？

はい。Draft issueとしてタイトルや本文を追加でき、Project内で後から整理できます。

GitHub FreeでBoardを使えますか？

はい。GitHubの料金ページではFreeプラン（月額0ドル）にIssues & Projectsが含まれています。

基本情報

確認日
2026-11-18
料金
GitHub Freeは継続して月額0ドルで、公式料金ページにIssues & Projectsが含まれます。この例のDraft issueとBoard整理はFreeプランで始められます。Codespacesなど別料金になりうる追加機能の費用は含めていません。
利用条件
GitHubアカウントとインターネット接続が必要です。チームで使う場合はProjectの閲覧・編集権限を整え、リンクした非公開リポジトリのIssueやPRは、そのリポジトリを閲覧できる人だけが開けることを確認してください。
補足
GitHub ProjectsはIssueやPRなどの作業を見渡すプロジェクト管理機能で、個別のAgent SkillやMCPサーバーではありません。記載した進行例は想定例で、実機検証やMMCでの導入実績を示すものではありません。
