# 毎日聴く音楽室 データ運用ガイド

## 管理ファイル

- `src/data/music-room-config.json`: 公開状態、使用する曲セット、質問、画面文言、演出時間を管理します。
- `src/data/music-room-tracks.json`: 1日から31日までの8ルート、合計248枠を管理します。
- `tools/mmc-cms/data/workline-employees.json`: 選曲担当のAI社員情報です。音楽室では `staffId` から参照します。
- `tools/mmc-cms/data/workline-departments.json`: AI社員の所属名を参照します。

## ルートの意味

回答はQ1、Q2、Q3の順に、YESを`Y`、NOを`N`として扱います。コードは画面へ表示しません。

| ルート | 今日の回答 |
| --- | --- |
| YYY | 楽しい・気分を動かしたい・言葉に浸りたい |
| YYN | 楽しい・気分を動かしたい・音や演奏を重視したい |
| YNY | 楽しい・今の気分に浸りたい・言葉に浸りたい |
| YNN | 楽しい・今の気分に浸りたい・音や空気感を重視したい |
| NYY | 少ししんどい・気分を変えたい・言葉に浸りたい |
| NYN | 少ししんどい・気分を変えたい・音で切り替えたい |
| NNY | 少ししんどい・今の気持ちに浸りたい・言葉に浸りたい |
| NNN | 少ししんどい・今の気持ちに浸りたい・音や空気感に浸りたい |

## 1〜31日の考え方

日本時間の「日にち」だけを使います。たとえば8月10日と9月10日は、どちらも`day: 10`の枠を参照します。同じ日、同じ回答ならリロードしても同じ曲です。存在しない日付の枠は、その月には使われません。

## 曲データの項目

| 項目 | 内容 |
| --- | --- |
| `id` | `d01-NNY`形式の一意なID |
| `setId` | 使用する31日セットの識別子 |
| `day` | 1〜31 |
| `route` | 8ルートのいずれか |
| `title` | 曲名 |
| `artist` | アーティスト名 |
| `staffId` | Workline社員JSONにある社員ID |
| `message` | AI社員からの短いコメント、40〜120文字程度 |
| `reason` | 回答と選曲をつなぐ説明、40〜160文字程度 |
| `tags` | 2〜5件の文字列配列 |
| `youtubeUrl` | 公式YouTubeのhttps URL |
| `spotifyUrl` | Spotifyのhttps URL |
| `directorNote` | 必要な場合だけ使う80文字程度までの所長メモ |
| `linkCheckedAt` | 公式リンクを確認した日付、`YYYY-MM-DD` |
| `published` | 画面へ出せる場合だけ`true` |

## 1件を編集する手順

1. `day`と`route`で対象枠を探します。
2. 曲名、アーティスト、`staffId`、コメント、理由、タグを入力します。
3. 公式YouTubeまたはSpotifyのリンクを最低1件入力します。
4. 公式チャンネル・公式配信ページであることを人間が確認し、`linkCheckedAt`を入力します。
5. 歌詞引用、心理状態の診断、無理な励ましがないことを確認します。
6. 最後に`published`を`true`へ変更します。
7. 検証コマンドを実行します。

## スプレッドシート・GASから出力する場合

- 1行を1曲として、JSONと同じ列名を使います。
- `day`は数値、`published`は真偽値、`tags`はJSON配列として出力します。
- 文字列を結合してJSONを作らず、GASの`JSON.stringify()`を使ってください。
- UTF-8で保存し、IDと`day + route`の重複を作らないでください。
- 空欄を埋めただけの枠は`published: false`のままにします。
- `setId`は設定JSONの`activeSetId`と一致させます。

## テンプレートの再生成

次のコマンドは248枠を空の状態で作り直します。入力済みデータも上書きするため、通常運用では実行しません。

```bash
python3 scripts/generate_music_room_tracks.py
```

## 検証と進捗

```bash
npm run validate:music-room
```

`npm`を使わない場合:

```bash
python3 scripts/validate_music_room.py
```

ルートごとに`公開可能件数 / 31`、最後に`合計 / 248`を表示します。データの重複、不正な日付・ルート、公開曲の必須項目、https URL、社員IDも同時に検証します。

## 公開前チェック

- 8ルートすべて31/31、合計248/248になっている
- 公式リンクを人間が開いて確認した
- 曲名、アーティスト名、社員ID、コメントを確認した
- NOを否定したり、ユーザーを診断したりする文章がない
- 歌詞を引用していない
- `music-room-config.json`の`isPublic`を切り替える前に所長の承認を得た
- 公開作業は実装レポートの手順を実施する
